§ Le besoin

La correction du travail papier (phase 24/26) était un unique long paragraphe généré par l'IA, sans structure exploitable côté frontend — "pas du tout joli", "on ne peut pas réviser facilement".

§ Les décisions de conception

  • Restructurer la sortie de l'IA, pas juste la mise en forme — le schéma JSON demandé à Azure OpenAI change : une synthese_globale courte + une liste points (1 à 8 selon la richesse réelle), chacun avec sujet/constat/correction_attendue.
  • Même patron @ElementCollection/@Embeddable que QcmMatiere.questions — nouvelle table travail_papier_points_correction, aucune migration risquée.
  • Accordéon replié par défaut, dépliable point par point, avec un bouton "Tout déplier/replier" — répond explicitement à "on peut étirer ou fermer quand on clique".

§ Limites connues, assumées

  • Pas de capture séparée de l'énoncé — la correction reste basée uniquement sur le texte extrait de la photo du travail, sans énoncé de référence fourni séparément.
  • Pas de mode interactif question par question ("apprentissage progressif avec simulation de partenaire de travail") — chantier séparé, proche du tuteur vocal mais ancré sur le travail de l'étudiant.

§ Pour reprendre seul

  • Code de référence exact : git checkout phase-27-correction-travail-papier-structuree
  • Prochaine étape naturelle : décider du mécanisme de capture de l'énoncé avant de construire le mode interactif question par question.
