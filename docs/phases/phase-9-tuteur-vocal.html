§ Le besoin

Le master prompt : "l'IA raconte le cours en dialogue vocal naturel comme un camarade present, vise 100% de maitrise, ne lache pas une notion tant qu'elle n'est pas comprise (change d'approche, analogies, reformulation), suit un score de maitrise par notion... propose un mode exercices. La seule sortie est l'arret par l'utilisateur, avec sauvegarde de l'etat." Etat avant cette brique : aucun modele Matiere/Seance/Promotion/Notion, aucun TTS implemente, STT existant reutilisable tel quel.

§ Les décisions de conception

  • Dialogue tour par tour (pas de streaming temps reel) — decide explicitement avec l'utilisateur, evite une infrastructure WebSocket/VAD hors de portee d'un seul increment.
  • Couloir reutilise comme "Promotion", aucune nouvelle entite — sa propre documentation (phase-5) le decrit deja comme "un espace partage par promotion". Le proprietaire du couloir joue le role enseignant, les membres jouent le role eleve.
  • NiveauMaitrise qualitatif (3 valeurs), pas un score numerique — une evaluation LLM est intrinsequement qualitative, un score 0-100 serait une fausse precision.
  • Pas d'audio persiste — resynthetise a la demande via un endpoint dedie, coherent avec l'absence de stockage de blobs ailleurs dans le projet.
  • "Change d'approche" = prompt engineering, pas une machine a etats — toute la nuance pedagogique vit dans le prompt systeme de l'adaptateur IA, verifie fonctionner en conditions reelles (voir §4).

Preuve concrete du comportement "ne lache pas une notion, change d'approche"

En reinjectant l'audio genere comme reponse etudiant (un test de plomberie), l'etudiant simule a repete la definition mot pour mot. Observe reellement, pas suppose :

TuteurLa dérivée mesure le taux de variation instantané d'une fonction... Dis-moi avec tes mots ce que cela signifie : que représente la dérivée en un point ?
ÉtudiantLa dérivée mesure le taux de variation instantanée d'une fonction... (répétition mot pour mot)
TuteurTu as repris la définition mot pour mot, donc je veux vérifier ta compréhension autrement. Pense à une voiture : la fonction donne sa position selon le temps...

niveauMaitrise est reste EN_COURS, la notion n'a pas avance -- exactement le comportement demande par le master prompt.

§ Limites connues, assumées

  • "Change d'approche" = prompt engineering — pas de suivi structure des approches deja tentees, pas de garde-fou si le modele finit par se repeter.
  • Pas de garde-fou anti-blocage — une seance peut tourner indefiniment sur une notion (arret manuel toujours possible). nombreTentatives suivi mais pas exploite.
  • Pas d'ancrage dans RechercheService — le tuteur utilise seulement Notion.definition, jamais la transcription reelle du cours. Seance.sessionId pret pour une extension future.
  • Mode exercices fixe au demarrage, pas de bascule en cours de route.
  • Pas de suivi enseignant en direct d'une seance de tutorat en cours.
  • Adaptateurs HTTP sans test unitaire — meme convention que les autres adaptateurs Azure du projet.

§ Pour reprendre seul

  • Chemin de bout en bout : Couloir (promotion) → Matiere → Notion(s) → Seance (rattache des notions) → demarrer le tutorat → boucle tour par tour → arreter.
  • Depuis l'UI : couloir (module Ecole) → "Matieres & tuteur vocal" → creer une matiere, des notions, une seance → rattacher les notions → "Demarrer le tutorat".
  • Prochaine direction possible : garde-fou anti-blocage (nombreTentatives), ancrage RechercheService via Seance.sessionId, suivi enseignant en direct.
