Le master prompt exige, "à partir de la Phase 2" : tests, analyse statique ("SonarQube ou équivalent"), vérification OWASP sur les points sensibles, scan des dépendances, couverture minimale. § Le besoin

Le master prompt : "À partir de la Phase 2, aucune PR n'est fusionnée sans : tests unitaires et d'intégration ; analyse statique (SonarQube ou équivalent) sans nouvelle dette critique ; vérification OWASP sur les points sensibles ; scan des dépendances (vulnérabilités connues) ; couverture de tests minimale." Le projet est bien au-delà de la Phase 2. État avant cette brique : CI à 3 jobs (tests backend seuls, lint+build frontend, build Docker garde-fou), aucun plugin de couverture/analyse statique/scan de dépendances, speaker-service absent de la CI.

§ Les décisions de conception

  • Équivalent auto-hébergé plutôt que SonarQube/SonarCloud — SonarCloud nécessite un compte externe + token que je ne peux pas créer moi-même, même raisonnement que terraform apply. JaCoCo + SpotBugs/FindSecBugs + GitHub Dependency Review couvre les 4 exigences non-test sans compte externe.
  • Rollout en une passe, seuils mesurés — pas de mode rapport temporaire : couverture mesurée reellement (52,6%), seuil fixé à 50% ; SpotBugs/FindSecBugs exécuté réellement, finding trié immédiatement.
  • Un seul finding réel, suppimé avec justification écrite — CSRF désactivé sur une API stateless JWT Bearer : pratique standard, pas un oubli. Jamais de suppression silencieuse.
  • Deux outils de scan de dependances essayes et abandonnes — OWASP Dependency-Check (NVD, impraticable meme avec cle API) puis Sonatype OSS Index (401 avale silencieusement), remplaces par GitHub Dependency Review, natif, zero compte. Voir §4.

§ Comment on a vérifié en conditions réelles

1

@SuppressFBWarnings sur une methode ne couvre pas un lambda

.csrf(csrf -> csrf.disable()) vit dans un lambda, compile en methode synthetique separee que SpotBugs analyse independamment de l'annotation posee sur la methode englobante. Corrige en deplacant l'annotation au niveau classe. Verifie : BugInstance size is 0.

2

OWASP Dependency-Check : impraticable meme avec une cle NVD, confirme en CI

Premier run local (sans cle) : 46% des 369587 enregistrements NVD apres ~80 minutes, interrompu -- verrou H2 corrompu, echecs en cascade sur les tentatives suivantes. Une fois une cle NVD_API_KEY obtenue et ajoutee en secret GitHub, le run en CI reelle a echoue a nouveau : Error: The operation was canceled. apres seulement 11% (40000/369802), timeout de 25 min depasse. Meme authentifie, le volume de donnees et les conditions reseau d'un runner ephemere ne permettent pas de completer ce premier sync. Pas un probleme de configuration : un probleme d'echelle structurel. Abandonne pour la CI.

3

Sonatype OSS Index : echoue silencieusement, rejete pour un defaut de conception

Remplacement teste : ossindex-maven-plugin, verification par dependance individuelle (pas de miroir complet). Local : BUILD SUCCESS en 39 secondes, mais le log montre 401 Unauthorized -- l'API anonyme Sonatype n'est plus accessible sans compte. Le vrai probleme : le plugin avale cette erreur en simple WARNING et continue, un BUILD SUCCESS qui ne veut rien dire puisqu'aucune dependance n'a ete verifiee. Pire qu'une absence de gate : un faux sentiment de securite. Rejete.

§ Limites connues, assumées

  • Pas de vrai SonarQube/SonarCloud — equivalent auto-heberge a la place.
  • Le scan de dependances Java ne se declenche que sur les PR — limite structurelle de GitHub Dependency Review (diff base vs head), pas sur un push simple.
  • speaker-service sans lint ni tests ni couverture — seul le scan de dependances est en place.
  • torch/torchaudio non couverts par pip-audit — angle mort documente.
  • Seuil de couverture (50%) documente la baseline, ce n'est pas un objectif actif.

§ Pour reprendre seul

  • Le scan de dependances Java se verifie sur l'onglet "Checks" d'une pull request GitHub, pas en local ni sur un push simple.
  • Lire un rapport JaCoCo/SpotBugs en local : voir docs/qualite.md §2.
  • Prochaine direction possible : tuteur vocal Ecole, ou faire monter le seuil de couverture progressivement.
