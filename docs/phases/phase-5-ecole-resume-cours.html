§ Le besoin

Après l'authentification (tag phase-5-securite-auth), la suite naturelle était de démarrer la couche École — le seul étage du roadmap encore entièrement à zéro (com.memoria.ecole n'existait pas). Le multi-tenant/couloirs et le passage à l'échelle ont été écartés pour l'instant : leur urgence réelle est faible tant qu'il n'y a qu'une seule instance.

Le master prompt regroupe sous "résumés adaptés au cours" : notions/définitions, exercices avec corrections, annonces, points à réviser, QCM auto-générés. Choisi avec l'utilisateur : périmètre réduit à synthèse + notions/définitions + points à réviser. Exercices, annonces et QCM sont chacun un chantier à part (les QCM demandent une UI de quiz distincte) — tout inclure d'un coup aurait été de la sur-ingénierie pour un premier jet.

§ Les décisions de conception

Copier le pattern du compte rendu, pas en réinventer un nouveau

Le projet a déjà un pattern éprouvé pour "extraction structurée par IA à la demande, avec traçabilité et mise en cache" : entreprise.compterendu. Cette brique le mirroire fichier par fichier.

Décisions reprises telles quelles : génération à la demande (discipline de coûts), garde d'idempotence revérifiée avant sauvegarde, échec persisté (ECHEC) plutôt que relancé, traçabilité au niveau du document via segmentsSources.

Pas d'événement publié — contrairement à CompteRenduGenereEvent (consommé par EngagementService), aucun consommateur n'existe côté École pour l'instant. Ne pas ajouter de mécanisme sans écouteur (YAGNI) ; le même patron pourra être reproduit le jour où une fonctionnalité (score de maîtrise, tuteur vocal) en a besoin.

public ResumeCours obtenirOuGenererResumeCours(UUID sessionId) {
    sessionService.obtenirSession(sessionId);
    Optional<ResumeCours> existant = resumeCoursRepository.findBySessionId(sessionId);
    if (existant.isPresent()) return existant.get();
    List<Transcription> reussies = transcriptionsReussies(sessionId);
    if (reussies.isEmpty()) throw new AucuneTranscriptionDisponibleException(sessionId);
    try {
        ResumeCoursGenere genere = generateurResumeCours.genererResumeCours(transcriptComplet);
        return enregistrerSiAbsent(sessionId, genere.synthese(), notions, genere.pointsARevoir(), segmentsSources, REUSSI);
    } catch (Exception e) {
        return enregistrerSiAbsent(sessionId, null, List.of(), List.of(), segmentsSources, ECHEC);
    }
}

§ Comment on a vérifié en conditions réelles

1

Vrai appel Azure OpenAI

Transcription de test sur la photosynthèse (définition, chlorophylle, cycle de Calvin à réviser) : POST /resume-cours → 3 notions distinctes extraites (Photosynthèse, Chlorophylle, Chloroplastes) avec définitions fidèles, 2 points à réviser correctement identifiés.

2

Mise en cache confirmée

GET /resume-cours → renvoie exactement le même résultat, pas de second appel Azure OpenAI. GET sur une session sans résumé → 204.

3

Vérifié dans un vrai navigateur

Playwright : la section "Résumé de cours (École)" s'affiche correctement — synthèse, notions en gras avec définition, liste des points à réviser — aucune erreur console. Données de test nettoyées ensuite.

§ Limites connues, assumées

  • Périmètre volontairement réduit — pas d'exercices avec corrections, pas d'annonces, pas de QCM auto-générés. Chacun est un chantier séparé.
  • Pas d'événement publié — aucun consommateur n'existe encore côté École.
  • Pas de couloirs/promotions — la notion de classe partagée n'existe pas encore ; ce résumé reste attaché à une session individuelle.
  • Traçabilité au niveau du document, pas par notion — même compromis déjà accepté pour le compte rendu.
  • Fenêtre de course non éliminée à 100% — même garde d'idempotence déjà acceptée ailleurs dans le projet.
  • Affichée sans condition de produit — pas de mécanisme pour n'afficher cette section qu'aux instances École.

§ Pour reprendre seul

  • Ajouter exercices/corrections ou QCM : nouveau champ/collection sur ResumeCours (ou entité dédiée si la complexité le justifie — les QCM ont besoin d'un état de réponse par utilisateur), nouveau prompt, même squelette GenerateurResumeCoursAzureOpenAI.
  • Chemin de bout en bout : bouton "Générer le résumé de cours" → ResumeCoursController → ResumeCoursService → GenerateurResumeCoursAzureOpenAI → ResumeCoursRepository → section "Résumé de cours (École)" de SessionDetailPage.tsx.
