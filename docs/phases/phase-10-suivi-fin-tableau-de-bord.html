§ Le besoin

Le master prompt : "Phase 5 -- Fonctionnalites avancees. Tuteur vocal et score de maitrise (ecole) ; suivi fin et tableaux de bord (entreprise)." Aucune spec dediee au-dela de cette ligne de roadmap. Tableau de bord existant : total, repartition par statut, taux de completion, en retard -- strictement agrege, contrainte ethique explicite du master prompt ("le manager voit l'avancement global, pas le detail permanent des retards individuels").

§ Les décisions de conception

  • Pas de nouvelle table d'historique — Engagement.dateDerniereMaj n'est modifie que par les transitions de statut, et la machine a etats est lineaire sans cycle : dateDerniereMaj d'un engagement TERMINE est donc fiable comme date d'entree dans cet etat. Tendance et delai moyen calculables directement, sans migration.
  • Limite induite assumee : le delai de l'etape intermediaire EN_ATTENTE→CONFIRME n'est plus calculable une fois l'engagement termine (l'horodatage de confirmation est ecrase). Seul le delai total creation→terminaison l'est.
  • Toujours pas de scope equipe/projet/client — aucun concept de ce type dans le modele Entreprise, coherent avec la contrainte ethique et la fiche precedente.
  • Graphique via la skill dataviz — palette validee (--color-brand + --color-ok, deja utilisees sur la meme page), flexbox/CSS pur (toujours aucune dependance de charting), legende toujours visible.

§ Limites connues, assumées

  • Delai de l'etape intermediaire non calculable une fois termine — necessiterait une vraie table d'historique.
  • Pas de scope equipe/projet/client — toujours aucun concept de ce type dans le modele.
  • Fenetre fixe a 8 semaines, pas de selecteur de periode.
  • Pas de vue tableau de secours pour le graphique — coherent avec le graphique existant qui n'en a pas non plus.

§ Pour reprendre seul

  • Prochaine direction possible : vraie table d'historique des transitions (si le delai par etape devient un besoin confirme), ou concept equipe/projet/client si demande explicitement.
